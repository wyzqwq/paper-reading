# v2 翻译后端部署指南

把 v2 翻译功能在线上跑起来要做的三件事:**建两张表** + **部署一个 Edge Function** + **设置页填 DeepSeek key**。前端代码已在本地(commit 151a9ee),push 不 push 都不影响后端这步。

- Supabase 项目 ref：`hjrrocbisrgtxgqnflpi`
- 线上 app：`https://wyzqwq.github.io/paper-reading/`

---

## 步骤 1：装 Supabase CLI（已装跳过）

```bash
brew install supabase/tap/supabase
supabase --version
```

## 步骤 2：登录 + 关联项目

```bash
cd /Users/wyzwyz/Claude/Projects/paper-reading
supabase login
supabase link --project-ref hjrrocbisrgtxgqnflpi
```

`login` 会开浏览器让你登 Supabase 账号授权 CLI；`link` 把本地 `supabase/` 目录关联到远程项目，会提示你确认项目名。

## 步骤 3：建表（Dashboard SQL Editor，推荐）

1. 浏览器打开：https://supabase.com/dashboard/project/hjrrocbisrgtxgqnflpi/sql/new
2. 打开文件 `supabase/migrations/0003_translate.sql`，整段复制粘贴进 SQL Editor
3. 点 **Run**（或 Ctrl+Enter）
4. 预期输出：`Success. No rows returned`

这会建 `user_secrets`（存 DeepSeek key）+ `translations`（存译文缓存）+ RLS 策略 + 索引。SQL 是幂等的，重复跑不报错。

> 备选 CLI 方式：`supabase db execute --file supabase/migrations/0003_translate.sql`。但 Dashboard 更直观、不依赖本地 migration 状态，推荐用 Dashboard。

## 步骤 4：部署 translate-proxy 函数

```bash
supabase functions deploy translate-proxy
```

预期输出：

```
Deployed Function translate-proxy on project hjrrocbisrgtxgqnflpi
        URL: https://hjrrocbisrgtxgqnflpi.supabase.co/functions/v1/translate-proxy
```

- `SUPABASE_URL` / `SUPABASE_ANON_KEY` 是 Supabase 部署时**自动注入**的，不用手动 `set`
- `verify_jwt=true` 从 `supabase/config.toml` 自动读，不用额外设置

## 步骤 5：验证后端通了（终端 curl）

```bash
curl -i https://hjrrocbisrgtxgqnflpi.supabase.co/functions/v1/translate-proxy
```

预期返回 `HTTP/2 401`（Missing Authorization header）—— 这说明函数已部署、`verify_jwt` 在正常拦截没带 JWT 的请求。

- `401` = 部署成功 ✓
- `404` / `Function not found` = 没部署成功，回步骤 4 看报错

> 到步骤 5 为止后端就部署完了，`curl` 拿到 401 即说明后端通了。下面步骤 6-7 是线上端到端验收，需要**前端也在线上是最新版**--本地代码（151a9ee）还没 push 到 GitHub，线上 Pages 还是旧版（没有翻译 UI），得先 push：
>
> ```bash
> cd /Users/wyzwyz/Claude/Projects/paper-reading
> git push origin main
> ```
>
> push 后 GitHub Pages 几分钟内重新部署，硬刷新（Cmd+Shift+R）能看到新版。这步命令是你自己跑，我不替你 push（按开发规范 push 需你本人确认）。

## 步骤 6：设置页填 DeepSeek key

1. 去 https://platform.deepseek.com 注册登录，创建一个 API key（账户充值几块钱即可，`deepseek-v4-flash` 很便宜）
2. 浏览器打开线上 app：https://wyzqwq.github.io/paper-reading/
3. 登录你的账号
4. 进设置页，找到 DeepSeek key 输入框，粘贴 key，点保存
5. key 会存到 `user_secrets` 表，受 RLS 保护，只有你自己能读

## 步骤 7：线上验收

打开一篇英文 PDF 论文，点翻译开关，逐项检查：

- 状态条从「翻译中」变成「译文就绪 N 页」
- 页面上出现半透明的中文译文叠层
- 点一句英文，弹出该句的中文译文浮层
- 翻到第二页，预译自动把译文铺上
- 关掉阅读器重开，再点翻译应该秒出（本地缓存命中，不再请求后端）
- 打开 DevTools → Network，看到 `translate-proxy` 请求返回 200，响应体里有 `sentences` 数组

到这步全绿，v2 翻译就在线上跑通了。

## Troubleshooting

- **步骤 3 报 `relation "papers" does not exist`**：`papers` 表没建。说明 M6 的建表 SQL 也没跑过。去 `supabase/migrations/` 找更早的 papers 建表 SQL，先跑那个再跑 0003。
- **步骤 4 报 `not linked to a Supabase project`**：回步骤 2 先 `supabase link`。
- **步骤 4 报找不到 config**：确认在 repo 根目录（`/Users/wyzwyz/Claude/Projects/paper-reading`）跑，CLI 要能读到 `supabase/config.toml`。
- **步骤 7 点翻译弹「未设置 DeepSeek key」**：步骤 6 的 key 没存成功。检查设置页保存是否成功，或 Dashboard 里看 `user_secrets` 表有没有你的行。
- **步骤 7 弹「DeepSeek key 无效」**：key 错了/过期，回 platform.deepseek.com 检查。
- **步骤 7 弹「DeepSeek 限速」**：稍等重试。若要换更稳的模型，改 `supabase/functions/translate-proxy/index.ts` 第 29 行 `DEEPSEEK_MODEL` 为 `deepseek-v4-pro`，重新 `supabase functions deploy translate-proxy`。
- **步骤 7 翻译返回但叠层没铺上**：多半是前端没更新到最新版。GitHub Pages 有缓存，等几分钟或硬刷新（Cmd+Shift+R）。确认前端已 push 到 main。
