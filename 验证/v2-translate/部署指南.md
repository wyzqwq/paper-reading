# v2 翻译后端部署指南（纯 Dashboard 手动版，不用 CLI）

全程浏览器操作,做三件事:**建两张表** + **部署一个 Edge Function** + **设置页填 DeepSeek key**。前端代码已在本地(commit 151a9ee),后端部署完就能线上验收。

- Supabase 项目 ref：`hjrrocbisrgtxgqnflpi`
- 线上 app：`https://wyzqwq.github.io/paper-reading/`

---

## 步骤 1:建表（Dashboard SQL Editor）

1. 浏览器打开：https://supabase.com/dashboard/project/hjrrocbisrgtxgqnflpi/sql/new
2. 打开文件 `supabase/migrations/0003_translate.sql`，整段复制粘贴进 SQL Editor
3. 点 **Run**（或 Ctrl+Enter）
4. 预期输出：`Success. No rows returned`

这会建 `user_secrets`（存 DeepSeek key）+ `translations`（存译文缓存）+ RLS 策略 + 索引。SQL 是幂等的,重复跑不报错。

## 步骤 2:部署 translate-proxy 函数（Dashboard）

1. 浏览器打开：https://supabase.com/dashboard/project/hjrrocbisrgtxgqnflpi/functions
2. 这里你能看到已部署的 `arxiv-proxy`(app 在用),在它旁边点 **New Function**(或 Create Function,右上角)
3. **Name** 填：`translate-proxy`（必须这个名,前端按这个路径调）
4. **代码编辑器**：把默认模板全选删掉,粘贴 `supabase/functions/translate-proxy/index.ts` 的全文
5. **Verify JWT**：打开/勾选（必须,和设计一致,防未授权调用盗用你的 DeepSeek 额度）
6. 点 **Deploy** / **Create**

部署成功后,函数列表里能看到 `translate-proxy`,URL 是 `https://hjrrocbisrgtxgqnflpi.supabase.co/functions/v1/translate-proxy`。

- `SUPABASE_URL` / `SUPABASE_ANON_KEY` 是 Supabase **自动注入**的,不用手动配 env
- 函数代码里 `Deno.env.get('SUPABASE_URL')` 能直接拿到

> Dashboard 版本不同,按钮名/菜单位置可能略有差异(左侧可能叫 Edge Functions 或 Functions)。核心就一句:**建一个叫 `translate-proxy` 的函数,粘贴代码,开 Verify JWT,部署**。找不到对应按钮就截图发我。

## 步骤 3:验证后端通了

浏览器地址栏直接访问(或终端 curl):

- 浏览器打开:https://hjrrocbisrgtxgqnflpi.supabase.co/functions/v1/translate-proxy
- 预期看到 401 错误 JSON,类似 `{"code":"401","message":"Missing Authorization header..."}`

判读：

- `401` = 部署成功 ✓（verify_jwt 在正常拦截没带 JWT 的请求）
- `404` / `Function not found` = 没部署成功,回步骤 2 看日志

## 步骤 4:push 前端到 GitHub

线上验收需要前端也是最新版--本地代码(151a9ee)还没 push,线上 Pages 还是旧版(没有翻译 UI),得先 push:

```bash
cd /Users/wyzwyz/Claude/Projects/paper-reading
git push origin main
```

push 后 GitHub Pages 几分钟内重新部署,硬刷新(Cmd+Shift+R)能看到新版。这步命令是你自己跑,我不替你 push(按开发规范 push 需你本人确认)。

> 如果你只想先验证后端部署成功,做完步骤 1-3 就够了(拿到 401 即后端通了)。步骤 4-6 才是线上端到端验收。

## 步骤 5:设置页填 DeepSeek key

1. 去 https://platform.deepseek.com 注册登录,创建一个 API key(账户充值几块钱即可,`deepseek-v4-flash` 很便宜)
2. 浏览器打开线上 app：https://wyzqwq.github.io/paper-reading/
3. 登录你的账号
4. 进设置页,找到 DeepSeek key 输入框,粘贴 key,点保存
5. key 会存到 `user_secrets` 表,受 RLS 保护,只有你自己能读

## 步骤 6:线上验收

打开一篇英文 PDF 论文,点翻译开关,逐项检查:

- 状态条从「翻译中」变成「译文就绪 N 页」
- 页面上出现半透明的中文译文叠层
- 点一句英文,弹出该句的中文译文浮层
- 翻到第二页,预译自动把译文铺上
- 关掉阅读器重开,再点翻译应该秒出(本地缓存命中,不再请求后端)
- 打开 DevTools -> Network,看到 `translate-proxy` 请求返回 200,响应体里有 `sentences` 数组

到这步全绿,v2 翻译就在线上跑通了。

## Troubleshooting

- **步骤 1 报 `relation "papers" does not exist`**:`papers` 表没建。说明 M6 的建表 SQL 也没跑过。去 `supabase/migrations/` 找更早的 papers 建表 SQL,先跑那个再跑 0003。
- **步骤 2 找不到 New Function 按钮**:Dashboard 可能改版,左侧找 Functions / Edge Functions 菜单(和 arxiv-proxy 在同一个列表页)。找不到就截图发我。
- **步骤 2 部署后访问还是 404**:函数名拼写错(必须正好是 `translate-proxy`),或部署时报错没看成。回函数详情页看 Logs。
- **步骤 3 返回 200 而不是 401**:`Verify JWT` 没开。回步骤 2 重新编辑函数,打开 Verify JWT 再 Deploy。
- **步骤 6 点翻译弹「未设置 DeepSeek key」**:步骤 5 的 key 没存成功。检查设置页保存是否成功,或 Dashboard 里 Table Editor 看 `user_secrets` 表有没有你的行。
- **步骤 6 弹「DeepSeek key 无效」**:key 错了/过期,回 platform.deepseek.com 检查。
- **步骤 6 弹「DeepSeek 限速」**:稍等重试。若要换更稳的模型,改 `supabase/functions/translate-proxy/index.ts` 第 29 行 `DEEPSEEK_MODEL` 为 `deepseek-v4-pro`,回步骤 2 重新粘贴代码 Deploy。
- **步骤 6 翻译返回但叠层没铺上**:多半是前端没更新到最新版。GitHub Pages 有缓存,等几分钟或硬刷新(Cmd+Shift+R)。确认前端已 push 到 main。
